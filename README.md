# STORM Studio — Telegram Mini App

STORM Studio هو متجر خدمات رقمية بواجهة عربية RTL ولوحة إدارة للطلبات والمدفوعات والخدمات ومعرض الأعمال. يعمل كتطبيق Node.js واحد داخل Docker على Dokploy، وتُحفظ بياناته في Supabase بدل ملفات JSON المحلية. صور إثبات الدفع تُحفظ في Supabase Storage الخاص.

## ما يتضمنه المشروع

- متجر متجاوب لخدمات بوتات تيليجرام وMini Apps والمواقع.
- نموذج طلب حسب الخدمة، مع اختيار حتى 3 ألوان لمشاريع Mini App.
- لوحة `/admin` محمية بمتغير `ADMIN_SECRET`: إدارة الطلبات وحالات التنفيذ وملاحظات العميل والخدمات والأسعار والمشاريع وعناوين المحافظ.
- الدفع اليدوي بـ USDT على شبكة TON أو GRAM بعد ضبط سعر GRAM. يرسل العميل TXID وصورة إثبات، وتراجع الإدارة التحويل يدويًا.
- بوت تيليجرام اختياري لفتح التطبيق وإرسال إشعارات الطلبات.
- قاعدة بيانات Supabase للجداول والإعدادات والطلبات، وحاوية Storage خاصة لإيصالات الدفع. روابط الإيصالات المعروضة مؤقتة الصلاحية.

## 1. تجهيز قاعدة بيانات Supabase

1. افتح مشروعك في [Supabase](https://supabase.com/dashboard)؛ يمكنك استخدام قاعدة المشروع الحالية.
2. افتح **SQL Editor** ثم **New query**.
3. انسخ محتوى الملف `supabase_schema.sql` كاملًا إلى المحرر واضغط **Run**. يضيف جداول الاستضافة المنفصلة والفهارس ودالة الحفظ وحاوية التخزين الخاصة `storm-hosting-files` مع الإبقاء على حاوية إثباتات الدفع.
4. من **Project Settings → API** تأكد من إعداد **Project URL** ومفتاح **service_role / Secret key** الخاص بالسيرفر.

شغّل ملف SQL قبل نشر هذه النسخة. لا تستخدم مفتاح `anon` بدل مفتاح السيرفر. لا تشارك `SUPABASE_SERVICE_ROLE_KEY` مع أحد ولا تضعه في ملفات الواجهة أو أي متغير يبدأ بـ `VITE_`.

## 2. متغيرات البيئة

أضف هذه المتغيرات في إعدادات بيئة Dokploy. المتغيران الأولان مطلوبان لتشغيل قاعدة البيانات والتخزين:

| المتغير | مطلوب؟ | الاستخدام |
|---|---|---|
| `SUPABASE_URL` | نعم | عنوان مشروع Supabase مثل `https://abcxyz.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | نعم | المفتاح السري المخصص للسيرفر من إعدادات API في Supabase |
| `ADMIN_SECRET` | نعم | كلمة مرور لوحة الإدارة، استخدم سرًا عشوائيًا طويلًا من 32 حرفًا أو أكثر |
| `PORT` | لا | المنفذ الداخلي، الافتراضي `3000` |
| `BOT_TOKEN` | لا | توكن بوت تيليجرام من `@BotFather`؛ ويمكن استخدام `TELEGRAM_BOT_TOKEN` بدلًا منه |
| `BOT_USERNAME` | لا | اسم البوت من دون `@` |
| `WEBAPP_URL` | لفتح التطبيق من البوت | رابط HTTPS النهائي من دون `/` أخيرة |
| `ADMIN_TELEGRAM_ID` | لا | رقم حساب/مجموعة تيليجرام لاستلام إشعارات الطلبات |
| `NODE_ENV` | لا | اتركه `production` للنشر |

تقدر تستخدم ملف `.env.example` كقائمة مرجعية عند التشغيل المحلي، ثم تملأ القيم الحقيقية في `.env`. لا ترفع ملف `.env` إلى GitHub.

## 3. التشغيل والنشر على Dokploy

1. ارفع مجلد المشروع إلى GitHub أو اربطه بمستودع Git.
2. في Dokploy أنشئ تطبيقًا من نوع **Dockerfile** واجعل Build Context هو مجلد `STORM-Studio`.
3. اضبط المنفذ الداخلي على `3000`، وأضف متغيرات البيئة أعلاه.
4. نفّذ Deploy. يثبّت Docker اعتماديات Node.js أثناء البناء.
5. بعد نجاح النشر افتح رابط الدومين. المتجر على `/` ولوحة الإدارة على `/admin`.

لم تعد تحتاج إلى تركيب Volume من أجل حفظ الطلبات أو صور الإيصالات؛ قاعدة البيانات والملفات محفوظة في Supabase. احتفظ بنسخة احتياطية من قاعدة البيانات إذا بدأت باستقبال طلبات حقيقية.

**مهم:** شغّل نسخة واحدة من التطبيق في Dokploy لهذا الإصدار؛ التطبيق يحتفظ بنسخة عمل من بياناته في ذاكرة السيرفر ويزامنها مع Supabase، كما يستخدم البوت Long Polling. تشغيل عدة نسخ بالتوازي قد يسبب تضاربًا في البيانات أو تحديثات البوت.

## 4. التشغيل محليًا

يحتاج Node.js 22 أو أحدث:

```bash
cp .env.example .env
# عدّل .env وضع مفاتيح Supabase وADMIN_SECRET الحقيقية
npm install
npm start
```

افتح `http://localhost:3000` للمتجر و`http://localhost:3000/admin` للوحة الإدارة. إذا لم تشغّل ملف SQL أولًا، سيظهر خطأ واضح في سجل السيرفر يفيد بأن مخطط قاعدة البيانات غير جاهز.

## 5. ربط بوت تيليجرام

- أنشئ بوتًا عبر `@BotFather` وضع التوكن في `BOT_TOKEN`.
- ضع رابط الموقع العام مع HTTPS في `WEBAPP_URL`.
- ضع اسم البوت دون `@` في `BOT_USERNAME` عند الحاجة.
- ضع رقمك في `ADMIN_TELEGRAM_ID` لتصلك إشعارات الطلبات، ثم افتح محادثة مع البوت واضغط `/start`.
- أعد النشر بعد تغيير المتغيرات. شغّل نسخة واحدة فقط من التطبيق إذا كان البوت يستخدم Long Polling.

## 6. إعداد الدفع قبل استقبال الطلبات

- راجع عنوان محفظة USDT على TON وعنوان GRAM من `/admin`. القيمة الافتراضية الموجودة في المشروع ليست تأكيدًا بأن العنوان نفسه يدعم العملتين.
- خيار GRAM يتطلب ضبط سعر `gramUsdRate` من لوحة الإدارة؛ يظل معطلًا عندما يكون السعر صفرًا.
- لا يتحقق التطبيق تلقائيًا من التحويل على البلوكشين. افحص TXID والعنوان والشبكة والمبلغ يدويًا قبل اعتماد الدفع.
- تجهيز تكامل Adsgram لا يضمن قبول التطبيق أو توفر الإعلانات أو دخلًا معينًا.

## الملفات المهمة

- `server.js`: API وخادم الواجهة وتشغيل البوت.
- `lib/store.js`: قراءة وحفظ حالة التطبيق في جداول Supabase.
- `lib/supabase.js`: اتصال Supabase وإدارة صور إثبات الدفع الخاصة.
- `lib/mini-express.js`: طبقة HTTP خفيفة باستخدام Node.js.
- `lib/telegram-bot.js`: عميل Telegram Bot API.
- `public/`: واجهة المتجر ولوحة الإدارة.
- `supabase_schema.sql`: SQL كامل لإنشاء مخطط قاعدة بيانات STORM Studio وتجهيز Storage.

## 7. قسم الاستضافة المستقل

راجع ملف `HOSTING_SETUP_AR.md` للحصول على تعليمات واجهة الاستضافة والإعدادات المطلوبة. تبويب الاستضافة منفصل عن الخدمات المعتادة في المتجر ولوحة الإدارة. بعد تأكيد الدفع ينشأ اشتراك برقم تسلسلي، ويمكن للعميل رفع ZIP (حد أقصى 500KB) وكتابة ENV كنص داخل الصفحة، ويستطيع الأدمن تنزيل ZIP ومراجعة/تعديل متغيرات البيئة وتمديد الاشتراك. تبدأ مدة الاشتراك عند تأكيد المشغّل أول تشغيل ناجح.

**الاستضافة اليدوية:** يرفع العميل ZIP (حد أقصى 500KB) ويكتب ENV كنصًا، ويُحفظان في التخزين الخاص، ثم تنزّل الملفات وتشغّلها على مزوّد استضافة تديره بنفسك. بعد التحقق من التشغيل اضغط «تأكيد التشغيل وتفعيل الاشتراك». لا يحتاج هذا المسار إلى `HOSTING_RUNNER_URL`. أوقف المشروع من مزوّدك أولًا قبل تسجيل الإيقاف في لوحة STORM. راجع `HOSTING_SETUP_AR.md` للتفاصيل.
